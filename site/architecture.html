Architecture

How the layers fit together, what each file does, what is intentionally hidden, and how to extend the system.

Design Principles

Deterministic

CUE's constraint engine guarantees that schema validation and default resolution produce identical output for identical input. No ambient state, no environment leakage.

Minimal Surface

Users interact with 4 fields. The build system's internal complexity — compiler flags, linker invocations, platform detection — is fully encapsulated.

No Runtime Parsing

Configuration is compiled into typed Zig constants. The build script contains zero parsing logic, zero error handling for malformed config, zero allocations.

Layer Separation

CUE is purely declarative — it never executes build steps. Zig is purely execution — it never validates configuration. Each layer has exactly one responsibility.

Build Engine Internals

build.zig is approximately 40 lines and implements a simple two-pass algorithm:

Pass 1 — Create Steps

Iterates spec.modules and creates the appropriate Zig build step for each module (addExecutable, addStaticLibrary, or addSharedLibrary). Each step is stored in a StringHashMap keyed by module name.

Pass 2 — Link Dependencies

Iterates again. For each module, resolves deps by name lookup and calls linkLibrary. Executables are registered with b.installArtifact.

Two passes are needed because a module's dependencies may be defined later in the array.

Extending Azazel

Adding a New Profile

  1. Add the value to #Profile in schema.cue
  2. Add its optimize mapping to the profiles struct
  3. Use it in project.cue

Adding a New Module Kind

  1. Add the value to #Kind in schema.cue
  2. Add a matching switch arm in build.zig
  3. Update gen_build_spec.sh if the new kind requires different codegen

Future Directions

These extensions are under consideration for the Azazel + Zaza ecosystem:

  • Multi-platform matrix expansion — define targets for multiple OS/arch combinations from a single project file
  • Feature toggles — conditional compilation flags controlled from CUE
  • Test targets — first-class test module definitions with kind: "test"
  • Package integration — CUE-defined dependency resolution for Zig packages
  • Remote cache compatibility — content-addressable build artifacts for CI/CD pipelines
  • C/C++ interop modules — leveraging Zaza's CMake and C toolchain integration
