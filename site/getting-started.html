Getting Started

Install dependencies, clone the repo, and build your first Azazel project in under two minutes.

Prerequisites

ToolVersionPurpose
Zig0.14.0+Compiler and build engine
CUEv0.16.0+Schema validation and constraint resolution
Python 33.8+Codegen script (gen_build_spec.sh)
macOS Install both with Homebrew: brew install cue zig

Clone and Build

git clone https://github.com/godofecht/azazel.git
cd azazel

Generate the Zig build spec from the CUE configuration, then compile:

./gen_build_spec.sh   # CUE validates → generates build_spec.zig
zig build             # compiles everything declared in the spec

Run

./zig-out/bin/app

The default project defines a static library (core) and an executable (app) that links against it. The executable is installed to zig-out/bin/.

Development Workflow

1. Validate your configuration

Check project.cue against the schema without generating anything:

cue vet

This catches type errors, invalid enum values, and missing required fields before any code is generated.

2. Inspect the resolved configuration

See the fully normalized build data that CUE produces:

cue export -e build

This shows you exactly what will be generated — all defaults resolved, all profiles expanded.

3. Generate and build

./gen_build_spec.sh && zig build

Project Structure

azazel/
├── schema.cue          # Type system (rarely edited)
├── project.cue         # Your modules (the only file you edit)
├── export.cue          # Wires modules to codegen output
├── gen_build_spec.sh   # CUE → build_spec.zig
├── build_spec.zig      # Generated (gitignored)
├── build.zig           # Zig build interpreter
└── src/
    ├── main.zig
    └── core.zig
Key insight project.cue is the only file you routinely edit. The schema, codegen, and build engine are infrastructure — set once, never touched.
