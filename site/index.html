Azazel

A deterministic build configuration layer powered by CUE for constraint validation and Zig for execution. The configuration frontend for Zaza.

Deterministic No JSON Runtime Compile-time Only Zero Ceremony

How It Works

Azazel replaces YAML, TOML, and JSON build configuration with a type-safe CUE schema that generates Zig source code directly. No parsing happens at build time — the configuration is baked into your binary as compile-time constants.

  1. Edit project.cue — declare your modules, dependencies, and profiles in under 15 lines
  2. Run ./gen_build_spec.sh — CUE validates against the schema and emits a typed Zig source file
  3. Run zig build — the Zig compiler reads the spec at compile time with zero parsing overhead

Quick Start

git clone https://github.com/godofecht/azazel.git
cd azazel
./gen_build_spec.sh    # validate + generate
zig build              # compile
./zig-out/bin/app      # run

Why Azazel?

Deterministic

CUE's constraint-based type system guarantees schema validation and default resolution. Same input always produces the same output.

Minimal Surface

Users interact with exactly 4 fields: kind, root, deps, and profile. Nothing else leaks through.

No JSON Runtime

CUE generates Zig source code directly. No std.json, no YAML parser, no runtime config loading. Pure compile-time constants.

Separation of Concerns

CUE handles declarations and constraints. Zig handles compilation and linking. Each layer does exactly one thing well.

What It Looks Like

A complete two-module project configuration:

package build

core: #Module & {
    kind: "static"
    root: "src/core.zig"
}

app: #Module & {
    kind:    "exe"
    root:    "src/main.zig"
    deps:    ["core"]
    profile: "release"
}

That's it. No flags, no platform triples, no macro syntax, no include paths. Everything else is resolved by schema defaults.

Relationship to Zaza

Azazel is the declarative configuration frontend for Zaza, a Zig-driven build system for modern C, C++, Zig, CMake-interop, and WebAssembly workflows. Where Zaza handles the full build execution pipeline, Azazel provides the type-safe configuration layer that feeds into it.

Note Azazel can be used standalone with any Zig project — it does not require Zaza. However, when paired with Zaza, it provides end-to-end deterministic builds from configuration through execution.
