Examples

Real-world project configurations demonstrating different build topologies. All examples are in the examples/ directory and can be tested by copying to project.cue.

Minimal — Single Executable

The smallest valid Azazel project. One executable, no dependencies, debug optimization by default.

package build

app: #Module & {
    kind: "exe"
    root: "src/main.zig"
}

export.cue modules:

_modules: { "app": app }

Produces one binary at zig-out/bin/app.

Library + Executable

The default Azazel project. A static library linked into an executable with release optimization.

package build

core: #Module & {
    kind: "static"
    root: "src/core.zig"
}

app: #Module & {
    kind:    "exe"
    root:    "src/main.zig"
    deps:    ["core"]
    profile: "release"
}

export.cue modules:

_modules: { "core": core, "app": app }

Multi-Library — Shared + Static + Exe

Demonstrates mixed library types. A shared math library, a static utils library, and an executable linking both.

package build

math: #Module & {
    kind:    "shared"
    root:    "src/math.zig"
    profile: "release"
}

utils: #Module & {
    kind: "static"
    root: "src/utils.zig"
}

app: #Module & {
    kind:    "exe"
    root:    "src/main.zig"
    deps:    ["math", "utils"]
    profile: "release"
}

export.cue modules:

_modules: { "math": math, "utils": utils, "app": app }

Microservice — Protocol + Two Services

A shared protocol library consumed by two independent service binaries. All modules optimized for production.

package build

protocol: #Module & {
    kind:    "static"
    root:    "src/protocol.zig"
    profile: "release"
}

gateway: #Module & {
    kind:    "exe"
    root:    "src/gateway.zig"
    deps:    ["protocol"]
    profile: "release"
}

worker: #Module & {
    kind:    "exe"
    root:    "src/worker.zig"
    deps:    ["protocol"]
    profile: "release"
}

export.cue modules:

_modules: { "protocol": protocol, "gateway": gateway, "worker": worker }

Using an Example

  1. Copy the example to project.cue
  2. Update the _modules map in export.cue
  3. Create the corresponding source files in src/
  4. Run ./gen_build_spec.sh && zig build
Tip All examples include their corresponding export.cue modules map. When switching examples, always update both files together.
